# 响应式检查（2026-09-10）

## 验收目标

内容能够放进可用视口时，不产生多余纵向滚动；不出现文档横向溢出。内容确实超过屏幕、软键盘缩小可用高度或横屏高度不足时，关键按钮和文件列表必须可以滚动到并操作，不得被固定导航挡住。

## 覆盖范围

17 种 CSS 视口：320×568、360×640、375×667、390×664、393×659、430×739、568×320、844×390、750×750、768×1024、820×980、1024×650、1280×746、1366×768、1512×1000、1920×1080、2560×1080。

- Chromium 与 WebKit 两种浏览器引擎，中文、英文、日文。
- 登录、主机主页、添加主机弹窗、AI 设置、AI 运维、SSH 工作台、文件列表、文件编辑弹窗。
- 登录页检查一屏适配，并模拟可用高度缩短至 350px，验证密码输入和提交按钮可达。
- 补充触屏、3 倍像素密度、亮暗主题、密码显示、登录/注册切换、横竖屏切换。
- 截图位于 `design/responsive-audit/`。

## 结果

216 项组合用例最终通过：每种引擎各 102 项视口/语言/页面用例，加上 12 项触屏主题状态用例。初轮发现矮屏文件遮挡，修复后通过；并发测试期间的浏览器进程崩溃采用单进程重跑受影响项，全部通过。生产构建与源码格式检查通过。

## 修复

手机登录页使用紧凑的单列网格，短屏收起宣传标题；品牌与语言选择对齐，移除重复外边距，保留完整表单。移动端输入使用 16px 字体，避免 iOS 小字号输入触发自动放大。

高度不足 500px 的移动工作台保留最低可操作高度与底部滚动空间，修复文件条目被固定底部导航遮挡而无法点击的问题。

## 复查命令

```sh
cd web
E2E_ORIGIN=http://127.0.0.1:5173 npx playwright test -c playwright.responsive.config.ts
```

API、SSH、监控和文件数据使用测试夹具；此次验证针对界面，不将其视为真实服务器连接测试。WebKit 自动化不是实体 iPhone/iPad，软键盘及浏览器工具栏采用缩小视口近似；不能声称已经覆盖所有 iOS 系统版本、字体放大和浏览器设置。

## 后续：整页空白滚动边界

用户实机仍报告可以滚入整页空白，说明之前尺寸模拟通过不能证明实体浏览器滚动边界正常。此次将 HTML/body 固定为不可滚动的应用外框，`#root` 按可用视口高度承载内容滚动，弹窗同时锁定该滚动容器。

原有一屏适配断言改为检查真实滚动容器的 `scrollHeight`，不能再只检查文档高度。新增手机和平板的双引擎用例：实际滚到底部后继续输入滚轮事件，验证文档偏移仍为 0、登录页不产生内容滚动、长主机列表底部说明仍留在可见区域，并验证弹窗滚动锁及恢复。

本轮最终完整重跑 220 项，全部通过（Chromium + WebKit，串行运行 8 分钟），包含新增的 4 项滚动边界用例。生产构建与格式检查通过。上述通过结论仅限自动化环境；用户实机整页空白未在同一硬件上复现，修复采用明确约束浏览器文档边界的方式处理。
