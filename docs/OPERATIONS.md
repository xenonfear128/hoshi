# 部署运维

## 部署前

- 使用独立域名及有效 HTTPS，PUBLIC_ORIGIN 必须与浏览器地址完全一致。
- 数据库仅开放给应用。MASTER_KEY 与数据库备份分开保存，并验证恢复流程。
- 第一个账号创建后关闭公开注册。每个账号独立访问自身资源。
- 单应用实例部署；实时 SSH 保存在进程内，重启会关闭连接。
- 出站网络策略按用途设置：SSH 可访问你管理的网段，AI 默认只允许公网 HTTPS。不要给普通用户开放无约束的平台出站代理。
- 反向代理限流使用 TRUSTED_PROXY_CIDRS。默认 Compose 信任 172.16.0.0/12 的内部代理；若 Docker 网络不同，修改为实际代理网段。保持应用端口不直接对公网开放。

## 备份与恢复

```sh
docker compose exec -T db pg_dump -U remoter -Fc remoter > remoter.dump
```

备份包含加密数据、密码哈希、额度和账单事件，仍然属于敏感资产，应加密保存、控制权限。备份加密主密钥到不同安全位置，丢失主密钥将无法恢复 SSH/API 凭据。

恢复到隔离的新数据库并使用对应 MASTER_KEY；先验证账号登录、主机解密、账单余额，再切换访问入口。不要将生产备份直接提供给开发环境。

## 重启与中断

- 正在运行的 AI 任务标记 interrupted，不自动重新执行。
- 待结算 AI 预占额度在进程重启时退款；无法确定的上游成本由平台承担。
- 终端会话断开，远端已完成的修改不回滚。远端进程是否继续取决于程序、PTY 和 SSH 行为。
- 过期登录会话每小时清理，非运行中的 AI 任务默认保留 30 天，可通过 TASK_RETENTION_DAYS 设置 1–365 天。
- 文件上传使用同目录临时文件并最终重命名。进程崩溃可能留下 `.remoter-*.tmp` 或 `.remoter-edit-*` 文件；确认没有活跃传输后，由对应 SSH 用户清理。

## 密钥轮换

当前密文版本为 v1，禁止直接替换 MASTER_KEY。使用下述已测试的停机轮换工具，在事务中重新加密全部主机/凭据/AI 设置/任务并更新密钥校验记录。

## 健康与日志

`GET /healthz` 同时检查数据库可用性。默认日志只含服务状态及存储错误，不记录 SSH 输入输出、API Key 或完整模型请求。反向代理也不应记录 Authorization、Cookie 或请求体。

资源预算：每账号最多 12 个 SSH 连接，全局最多 256 个；登录哈希并发上限 4；AI 每账号每分钟最多 20 次；监控同账号同主机复用采集，磁盘数据低频刷新。根据部署容量调整后，应重新做压力测试。

## 文件编辑限制

文本保存先对比内容哈希并再次核对，然后执行原子替换。应用内并发保存有锁；外部程序仍可能在最终核对与替换之间修改文件，因为 SFTP 不提供通用 compare-and-swap。编辑活跃配置时应配合远端变更流程。

已提供离线密钥轮换命令：停止应用，生成并安全保存新密钥文件，然后运行 `remoter rotate-key /run/secrets/new_master_key`。命令使用当前 MASTER_KEY 解密，在单个数据库事务中重新加密全部敏感字段；失败则回滚。完成后将部署的 MASTER_KEY 文件替换为新密钥，再启动应用。数据库实例锁会阻止运行中轮换。

管理员重置密码：将新密码写到权限 0600 的临时文件，执行 `remoter reset-password user@example.com /secure/password-file`，完成后删除临时文件。该操作撤销此账号所有登录会话，不回显密码。

SSH/SFTP 初始化超时为 12 秒。上传请求和下载响应空闲超过 30 秒会终止，防止慢连接长期占用传输槽；文件字节持续传输时会刷新空闲期限。
