## 已确认的差异

Hoshi 每秒通过 SSH 读取 Linux /proc；磁盘和系统信息每 30 轮刷新。采集按账号与主机共享，最后一个订阅退出时取消。当前既依赖活动 SSH 连接，也没有监控历史持久化。

Komari 的常驻 Agent 采集 CPU、RAM、Swap、负载、磁盘容量、上下行速率与累计流量、TCP/UDP 连接数、进程数量、运行时间，以及可选 GPU 使用率、显存、温度。支持网卡包含/排除、挂载点选择、流量周期设置；常规报告的网络和磁盘结构主要是汇总值，不能据此宣称已有逐网卡历史、逐磁盘 I/O 明细。

Agent 主动通过 WebSocket 上报，含心跳、重连和 POST 回退。v2 使用 JSON-RPC 风格消息；服务端支持历史指标聚合、ICMP/TCP/HTTP 探测、离线和资源阈值告警。源码还包含远程终端、任务执行、文件操作以及高级网络测试；Hoshi 本次监控需求不必同时引入这些控制能力。README 宣传秒级展示，但实际采集间隔可配置，不能把所有安装都视为固定 1 秒。

## 推荐接入方式

新增独立 Go 二进制 `hoshi-agent`，在 Hoshi 中建设监控接收与查询模块。可审查后复用 Komari Agent 的平台采集代码，保留 MIT 声明与来源版本。上报协议由 Hoshi 管理，保留逐网卡、逐挂载点维度。

相比部署完整 Komari，这一方案可以沿用 Hoshi 的账号、主机、凭据、UI 和数据库，避免第二套账号与面板。相比直接兼容原版 Agent，专用协议能控制权限范围和指标维度。代价是需要维护 Agent 的发行、升级与平台测试。已有 Komari 节点的只读接入可后续做适配器，不作为第一版前置依赖。

## 添加与生命周期

添加主机界面新增“持续监控”模块，默认关闭，说明“关闭终端后仍持续采集运行状态、流量和告警”。开启后只显示安装方式与折叠的高级设置，避免继续拉长默认表单。

- 自动安装：按钮改为“保存并安装探针”。先保存主机，再提交可追踪安装任务。校验 SSH 指纹、系统和架构、服务管理器、权限、出站连通性、已有实例；选择受信版本并验证签名/摘要，通过现有 SSH/SFTP 通道部署。等待首个有效心跳才算启用完成。
- 手动安装：保存后提供限时、单次绑定凭证及安装引导。现有 SSH 凭据不交给探针。
- 安装任务不依赖当前弹窗存活；刷新页面可继续查看进度，安装失败不回滚已保存主机。任务幂等，重复点击不会安装多份服务。
- 非 root 能力以预检结果显示；系统级安装可通过已有授权 sudo，权限不足时保留主机并提供手动方式。第一版自动安装目标为 Linux amd64/arm64 + systemd；其他平台后续支持。
- 状态：未启用、待安装、安装中、在线、数据延迟、探针离线、安装失败、已停用。展示版本和最后上报时间。
- 探针离线只代表上报不可用，不直接判定机器宕机；SSH 是否可达单独显示。
- 设置中支持暂停采集、恢复、轮换凭证、升级、卸载。暂停、撤销接入和远程卸载是不同操作。卸载失败明确提示远端可能仍有程序，但撤销凭证立即生效。
- 删除主机按既有删除动作清理绑定与历史，并撤销接入；若选择远程卸载，先执行可追踪卸载任务，失败可单独处理。

## 功能范围

第一阶段交付闭环：可选安装、基础资源与逐网卡监控、后台持续采集、历史、离线/资源告警、生命周期管理。

| 能力 | Hoshi 设计 | 阶段 |
| --- | --- | --- |
| 主机资料 | 系统、内核、CPU/架构/核数、运行时间、探针版本 | 1 |
| CPU/内存 | CPU 总占用、1/5/15 分钟负载、RAM/Swap 使用情况 | 1 |
| 磁盘容量 | 按挂载点显示总量、已用、剩余、占用比例，去重与排除规则 | 1 |
| 网络用量 | 逐网卡及选定网卡汇总、上下行速率、峰值、日/月累计、周期配额 | 1 |
| 基础进程信息 | 进程数量、TCP/UDP 数量；不采集命令行环境变量 | 1 |
| 历史与状态 | 独立于 SSH 的持续记录、缺报空段、主机与探针重启事件 | 1 |
| 告警 | 离线、恢复、CPU/内存/磁盘阈值、流量额度；站内事件与可配置 Webhook | 1 |
| 网络质量 | 从指定主机探测 ICMP/TCP/HTTP(S)，延迟、探测失败率、可用率；区分探针不可用与目标失败 | 2 |
| 深度资源 | 逐核 CPU、磁盘 I/O、IOPS、接口错误/丢包、GPU/显存/温度，按平台能力展示 | 2 |
| 高级诊断 | 路由追踪、主动吞吐测试，按次触发并显示流量/运行时间预算 | 3 |
| AI 辅助 | 读取历史、告警与异常时段生成分析；执行仍走现有 SSH/AI 流程 | 3 |

阶段 2/3 列出的逐核、磁盘 I/O 等是 Hoshi 扩展建议，不是对 Komari 当前报告结构的复述。HTTP/TCP 的失败比例标为探测失败率，不冒充 ICMP 丢包率。

## UI 与图表

主页主机卡片展示小型状态灯、CPU/RAM、上下行速率和最后上报时间，保留 SSH 连接入口。点击监控区域打开完整监控视图，页签为“概览 / 网络 / 历史 / 事件 / 探针设置”。不把全部图表堆在主机列表。

工作台保持左监控、中央 SSH、下方文件区布局。启用且数据新鲜时使用探针数据，未启用时使用现有 SSH 临时采集；探针失联而 SSH 仍在线时可显示临时 SSH 数据，但明确标记来源和断档，不悄悄拼接成连续历史。

平板、手机的监控详情采用完整页面或宽阔面板，逐网卡明细可切换，不扩张左栏。沿用现有玻璃与模糊设计、动画、三语框架；本功能不改变背景样式。名称只显示当前语言：中文“探针监控”、English “Agent monitoring”、日本語“エージェント監視”。

网络图分开表示“速率”“累计用量”“连接质量”。默认展示选定网卡的 Rx/Tx 两条曲线，支持网卡筛选；排除 loopback，并提示 Docker bridge/veth 等虚拟接口合计可能重复统计。默认汇总尽量选择对外接口，无法可靠识别时要求选择统计接口。

速率提供 B/s 与 bit/s 切换。使用无过冲的单调曲线/线性退化，不平滑原始数值；悬停展示原值、时间与来源。历史保留平均值与峰值，离线留空，不跨空段连线。缺失指标显示“不支持/无权限/暂无数据”，不能显示为 0。

## 技术设计

数据路径：Agent 采集 → 出站 HTTPS/WSS → Hoshi 接收鉴权与校验 → 最新值缓存、聚合存储、告警 → 浏览器订阅和历史查询。

- Agent：Go + gopsutil，Linux 优先；普通专用用户运行。ICMP 所需权限单独申请，GPU 能力检测后开启。监控协议只接收采样配置与明确类型的探测任务，不提供任意 shell、文件读取或终端接口。
- Hoshi：沿用 Go/chi、PostgreSQL、React/TypeScript、ECharts。第一版使用进程内最新值缓存和有界批写队列，不预先引入 Redis 或独立时序数据库。
- Agent 认证独立于浏览器会话。每个节点只绑定一个 owner/host；服务端从认证绑定解析归属，不信任报告里的 owner/host 字段。绑定凭证 10 分钟有效且只用一次，交换为独立高熵上报凭证，服务端仅存校验摘要，可轮换撤销。
- 探针配置权限限制为专用服务用户可读；凭证不写 URL、命令行参数或日志，通过受保护配置文件/标准输入交付。主机和敏感采集元信息延用现有 Vault 加密，监控查询、告警和安装任务均按账号归属校验。
- 通过公开 HTTPS 域名接入，正常验证 CDN 证书；源站自签证书不构成跳过探针 TLS 校验的理由。接收路径禁缓存、允许 WSS，避免浏览器挑战拦截机器上报；POST 回退也有同等鉴权、速率与体积限制。
- 协议含版本、Agent ID、boot/session ID、序号、采集时间、服务端接收时间、能力集合。限制消息大小、指标维度数量和采样频率，重连指数退避加抖动。
- 断网提供有上限的本地短期缓冲，重传去重；过期数据只补历史，不触发实时“已恢复”或旧阈值告警。用服务端最后有效接收时间判断上报在线状态。
- 流量用实际间隔计算计数器差值；重启、网卡重建、回绕产生事件并重新建立基线，不能产生负速率或把重连差值算成瞬间峰值。累计流量来自持久化增量，按明确时区与账期汇总。

建议表：agent_bindings、agent_install_jobs、metric_samples、metric_rollups、monitor_events、alert_rules、alert_deliveries。敏感配置加密，数值指标按 owner/host 授权查询；限制标签维度，不把 IP、命令行、任意路径扩成无界标签。

建议 API：主机探针配置、安装任务与进度、单次注册、上报/心跳、主机最新指标订阅、时间段聚合查询、告警事件及规则。浏览器 CSRF/Origin 策略不应直接套到无浏览器 Origin 的探针端点，探针端点使用单独的节点认证。

## 初始参数与容量边界

以下都是 Hoshi 建议值，需实现后压测，不是 Komari 默认值或实测承诺：

- 默认采集/上报每 3 秒；用户选择精细监控时可 1 秒。
- 最新原始样本内存保留 10 分钟；持久化 10 秒桶 24 小时、1 分钟桶 30 天、1 小时桶 180 天。
- 桶保存 count/min/max/avg 与流量增量；丢包/失败率保存失败数和总数，跨桶按计数加权。
- 所有网卡/挂载点在一次主机采样中成批写入；按时间分区清理。必要时再拆独立时序存储。
- 50 台主机、每 10 秒一份历史采样约 43.2 万份/天。若一份平均 1 KB，仅有效载荷约 0.43 GB/天，实际索引、WAL、维度和聚合还会增加占用，不能按此直接给磁盘最低配置。
- 上报超过约 3 个周期显示数据延迟；持续 60 秒未收到有效心跳显示探针离线，告警宽限期默认 180 秒。支持持续阈值、恢复阈值、冷却和维护静默；探针断连期间不重复触发整机所有资源告警。

## 验收要点

关闭全部浏览器与 SSH 会话后仍持续采集；安装失败与重试不影响主机保存；探针断连与 SSH 状态分离；停用/撤销立刻阻断新数据；凭证不能跨主机写入或读取其他主机；升级/卸载有可追踪结果；重启后流量不出现尖峰；历史缺口不被平滑隐藏；CDN 重连和 POST 回退不丢归属或重复计数；手机与平板无需在狭小弹窗里操作完整监控页。
